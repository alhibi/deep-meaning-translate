# A2 — Android native engineering audit

Mission: independent, read-only audit of the Android shell of the "today" translator
(React SPA in Capacitor 8.6.2 — Kotlin bridge, Room, DataStore).
Task id: **task-2** (owner: native). Report file: this file only.

- **Audited baseline: commit `c897209` on `main`** (working tree was clean when the audit
  started, 2026-11-16 18:14). A peer's uncommitted device-verification fixes appeared in
  the tree while this audit ran (18:20–18:24): `src/lib/native/plugin.ts`,
  `src/routes/__root.tsx`, `vite.native.config.ts`, `android/gradle.properties`,
  `android/app/build.gradle.kts`, migration tests and a new
  `android/app/src/androidTest/java/today/fluently/app/BridgeInstrumentedTest.kt`.
  **All line numbers below are the `c897209` lines** unless explicitly marked "working
  tree". Findings were re-checked against the working tree; where a peer fix changes the
  status it is stated in the finding.
- Method: source inspection of all Kotlin/manifest/theme/config files, the installed
  Capacitor 8.6.2 / plugin sources under `node_modules`, the relevant TS bindings, read-only
  `adb` inspection of the running emulator, and cross-checking `docs/android/*.md` claims
  against code.
- No gradle build, `adb install`, or emulator interaction was performed (as instructed).
- No feature was executed under this report's control; runtime behaviour is
  **NOT_VERIFIED** unless stated otherwise.

Two environment notes that matter for device verification:

1. The brief said "API 37"; the running emulator is **API 35** (peer A7 report agrees).
2. Its WebView is **124**, i.e. below the `140` threshold that gates the Capacitor
   `SystemBars` patch. The emulator therefore exercises the _legacy_ SystemBars branch,
   not the code path the 1.0.2 keyboard fix changed (see A2-03).

## Verdict

The native shell is structurally sound for its size: one activity, one bridge plugin per
concern, Room + DataStore owned by Kotlin, no secrets, no provider SDK in the APK, HTTPS-only
network, no storage permission, SAF for backups, a small permission set, and a genuinely
careful degraded-boot story on paper.

It is **not ready to be called a stable daily-use Android release** on evidence available
today:

- **four P1 defects** stand between the current code and a trustworthy release — two break a
  core input/output feature on the device (dictation is impossible without a manifest
  permission Capacitor itself requires; the native "device voice" path cannot load its
  plugin), one is a **data-loss** path for the phrasebook/translation memory after a slow
  boot, and one leaves the 1.0.2 keyboard fix **incomplete for Android 7–10 devices with a
  WebView below 140** while the available emulator cannot exercise the fixed branch at all;
- the device-verification story is still the project's weakest point (TD17 remains open);
  nothing in this report was executed on a device by me, and the baseline commit shipped
  knowing that;
- several P2s are ordinary integration defects (back button dead on secondary routes,
  system-bar icons not following the app palette, TTS lifecycle races, import
  decode/atomicity) that a person would hit in the first week of daily use.

Severity counts: **P1 × 4, P2 × 9, P3 × 8** (21 findings).

   `MODIFY_AUDIO_SETTINGS` to the manifest (A2-01) and route `LinguaTts` registration
