# A5 — Android security & privacy audit

Status: **Independent source audit, 2026-11-16** at commit `c897209` (branch `main`; the working tree was clean at audit start).
Scope: security/privacy of the Android build and its server surface, not general product quality.
No source, config, build output or emulator was modified. Evidence is `path:line` in this tree.

Classification (docs/quality/testing.md): **VERIFIED** = source inspection and/or executed test
confirms; **OBSERVED** = seen in a running system; **SUSPECTED** = plausible, not confirmed;
**NOT_VERIFIED** = could not be tested here (device, APK, credentials).

## Verdict

**No P0 (data loss / RCE / key exfiltration) was found.** The core secrets boundary holds statically:
no provider key, no `.env`, and no secret-shaped literal exists in the packaged client assets or in
the server-facing code that reaches them; provider keys are read only in server modules.

The build is **not clean enough for distribution yet**:

1. **A5-01 (P1)** — three native endpoints read their request body with `request.json()` before any
   size bound, unlike their sibling endpoints. This is an unauthenticated remote resource-exhaustion
   path on the same Worker that serves the app, and it breaks the project's own "bounded JSON before
   a paid call" rule.
2. **A5-02 (P1)** — a release build silently falls back to the debug key with no guard and no log
   (the code comment claims a log line that does not exist). The produced release APK is debug-signed
   (TD18). A misconfigured upload build therefore looks successful and cannot ship.
3. **A5-03 (P2)** — the Android backup reader decodes UTF-8 in independent 1 MiB chunks, so a
   multi-byte Arabic/German character split across a buffer boundary corrupts the text, fails the
   SHA-256 check, and makes a _valid_ backup file unimportable. The backup is the user's only copy
   after uninstall (data-restore failure).
4. **A5-04…A5-07 (P2)** — a privacy-policy statement that is false inside the APK, a security
   boundary (CORS allowlist) with zero automated tests while docs claim tests exist, voice/dictation
   that is not stopped on background while docs claim it is, and the known unencrypted archive
   (TD19) with no recorded Android-side decision.
5. **A5-21 (P2)** — the **generated** assets Gradle will package currently enable WebView debugging
   (the tracked config says off); a release rebuilt without a fresh `cap sync` would ship a debuggable
   WebView. The 18:18 release APK itself is clean on this point.

Everything else is P3 hardening or documentation accuracy. **Device/TLS/WebView/runtime behaviour
remains NOT_VERIFIED** (no APK existed at audit time; emulator deliberately untouched).

## Evidence method

- Read the security-relevant code: `src/lib/native/*`, `src/routes/api/native/v1/*`,
  `src/lib/requestSafety.ts`, `src/lib/voice/speechRoute.server.ts`,
  `src/lib/translation/streamRoute.server.ts`, `src/lib/persistence/*`,
  all `android/app/src/main/java/**/*.kt`, manifest/res XML, Gradle files, `capacitor.config.ts`,
  `patches/@capacitor+android+8.6.2.patch`, and the Capacitor 8.6.2 Java sources under
  `node_modules/@capacitor/android`.
- Scanned the **built client inputs** for secrets: `android-web/` (what Capacitor packages),
  `android/app/src/main/assets/public/` (packaged copy — asset sets and `index.html` were byte-identical
  to `android-web/` at audit start; both were then rebuilt by teammates' fixes, see concurrency note),
  and `.output/public` (web deploy). Grep for provider key names, `sk-`,
  `AIza`, `AKIA`, `ghp_`, `eyJ…` JWTs, and `.env` files: **no hit** outside the server bundle.
- Read existing build intermediates (read-only): `android/app/build/intermediates/merged_manifests/release/…/AndroidManifest.xml`
  and `packaged_manifests`. The APKs appeared **during** the audit (release 18:18, debug 18:20). I copied them to `/tmp` and
  scanned them read-only: ZIP listing, asset/dex grep for secrets, the binary `AndroidManifest.xml`
  string pool, the APK Signing Block v2 certificate (parsed with `python3`+`openssl`), and the packaged
  `assets/capacitor.config.json` / `assets/public/`. Results below apply to that **18:18 release
  artefact**; it predates the concurrent working-tree fixes, so APK checks must be re-run after the
  final rebuild (see residual risk).
- Executed the CORS gate logic **as source** with Node 26 type-stripping in `/tmp` (no repo write,
  no build, no server): allowlist value `["https://localhost","capacitor://localhost","http://localhost"]`;
  missing `Origin` → 403; `https://localhost` → allowed; `https://evil.example`,
  `https://localhost.evil.example`, `https://localhost:8443`, `https://LOCALHOST` → denied;
  preflight → 204 with exact-origin `Access-Control-Allow-Origin`, no wildcard, `Vary: Origin`,
  methods `GET, POST, OPTIONS`, max-age 600; a thrown handler message is replaced by the generic 502.
  All valid assertions passed. This compensates for — and does not replace — the missing repo test (A5-05).
- Did **not** run Gradle, `npm run build`, `adb`, install, or anything on `emulator-5554`.
- Did **not** run `npm audit` (dependency vulnerabilities stay NOT_VERIFIED, as in the baseline).

## Verified strengths (do not regress)

- **No provider secret in the packaged client.** `android-web/`, the packaged `assets/public/` copy and `.output/public` contain none of `DEEPSEEK_API_KEY`, `OPENCODE_API_KEY`, `GEMINI_API_KEY`, `ELEVENLABS_API_KEY`, `ASSEMBLYAI_API_KEY`, and no key-shaped literal. Only `VITE_NATIVE_API_BASE` (value `https://fluently.today`, confirmed in `android-web/assets/config-*.js` and in the release APK) and `VITE_APP_VERSION` are compiled in. The **release APK itself** (482 entries) was also scanned — assets + `classes.dex` — with no provider-key name or key-shaped literal and no `.env`/keystore inside. `process.env` provider reads exist only in server modules/routes (`src/lib/translation/providers/deepseek.server.ts:25-28`, `src/lib/voice/speechRoute.server.ts:59,186`, `src/lib/native/handlers.server.ts:110`, `src/lib/assembly.functions.ts:22`).
- **Origin gate is exact and fails closed:** no `Origin` or a look-alike → no service; `Access-Control-Allow-Origin` reflects only allowlisted origins; `*` is never returned; `Vary: Origin`; preflight does not touch a provider/budget; the generic 502 hides thrown messages (`gate.server.ts:31-47,49-58,61-65,83-96`; executed).
- **CORS is correctly scoped to what the app sends** (`Content-Type, Accept`; methods GET/POST/OPTIONS; `Retry-After` exposed) — `gate.server.ts:36-45`; client sends only `Content-Type` and `credentials: "omit"`, `cache: "no-store"` (`src/lib/native/transport.ts:29-36`, `src/lib/native/rpc.ts`).
- **Transport:** cleartext refused and only system trust anchors accepted (`network_security_config.xml:5-8`, `AndroidManifest.xml:21-22`); base URL enforced HTTPS + single origin at runtime (`config.ts:29-54`) and compiled as `https://fluently.today`.
- **Backup at rest:** `allowBackup="false"` + `fullBackupContent="false"` + explicit cloud/device-transfer exclusions for database/sharedpref/file (`AndroidManifest.xml:14-16`, `data_extraction_rules.xml:6-14`); the merged release manifest confirms it (`android/app/build/intermediates/merged_manifests/release/processReleaseManifest/AndroidManifest.xml:31-44`) and no `backupAgent`. Debug builds are `applicationIdSuffix .debug` so they cannot collide with a real install.
- **Permissions minimal:** merged release manifest = `INTERNET`, `RECORD_AUDIO`, `VIBRATE` (from the haptics plugin) + an androidx signature permission; no storage/camera/location/foreground-service (`AndroidManifest.xml:9-11`; merged manifest `:16-29`). `<uses-feature microphone required="false">` keeps non-mic devices installable.
- **Exported components minimal and correct:** only the launcher `MainActivity` is exported (`AndroidManifest.xml:26-39`); providers (`FileProvider`, `InitializationProvider`) and the Room invalidation service are `exported="false"`; the only exported receiver is androidx profile-installer, guarded by `android.permission.DUMP` (merged manifest `:60-107`). **No pending intents** anywhere in app code (grep `PendingIntent`/`Notification`: none).
- **SAF, not paths:** import/export use `ACTION_CREATE_DOCUMENT`/`ACTION_OPEN_DOCUMENT` and never construct a filesystem path (`LinguaFilesPlugin.kt:25-37,59-70`) → no traversal surface from JS-supplied names (the name is only `EXTRA_TITLE`). Import is capped at 8 MiB while streaming (`:81-93`); no zip/compression is involved, so no zip-bomb path.
- **Backup crypto is sound:** AES-256-GCM with a fresh 16-byte salt and 12-byte IV per export, PBKDF2-SHA256 at 210 000 iterations, password never stored, wrong password/decrypt failure is a generic refusal, future `schemaVersion` refused before any write (`src/lib/persistence/backup.ts:149-184,207-248`; covered by `src/lib/persistence/persistence.test.ts`). Imported rows/settings are re-validated (`cleanData`, `parsePrefs`, `parseSession`, `isEntry`, `isPhrase`, `isMemoryRow` — `backup.ts:89-119`), and the Kotlin write is one transaction with a compensating rollback (`LinguaRepository.kt:168-246`).
- **Kotlin never logs user data:** no `Log.`/`println`/`printStackTrace` in `android/app/src/main/java`; bridge rejections use fixed messages ("device storage unavailable", "could not read the backup file") that carry no SQL/value/URL/stack (`LinguaStorePlugin.kt:71-81`; `LinguaFilesPlugin.kt:54-56,100-102`). Server logs are metrics-only (`src/lib/translation/streamRoute.server.ts:124-136`, `src/lib/native/handlers.server.ts:33-42`).
- **WebView debug/mixed content off** in both configs (`capacitor.config.ts:18-26`, `android/…/assets/capacitor.config.json:6-14`); bridge is exposed only to the app origin through `WebMessageListener` (`Bridge.java:240`, `MessageHandler.java:36`); external links are handled by `ACTION_VIEW` outside the app (`Bridge.java:389-427`).
- **"Forget everything" is complete on native:** `clearDeviceData()` clears saved/history/memory caches first, then `persist.clearAll()` → `nativePort.clearAll()` → one Room transaction + `DataStore.clear()` (`src/lib/clearData.ts:15-21`, `src/lib/persist.ts:89-95`, `src/lib/persistence/native.ts:178-180`, `LinguaRepository.kt:248-257`).
