## Baseline blocker: the lockfile could not install

`npm ci` failed before any gate ran:

```
npm error `npm ci` can only install packages when your package.json and package-lock.json
or npm-shrinkwrap.json are in sync.
npm error Invalid: lock file's @lovable.dev/vite-tanstack-config@2.26.5 does not satisfy
@lovable.dev/vite-tanstack-config@2.27.1
```

This is a release blocker, not a local annoyance: CI runs `npm ci` as its first step, so every push
would fail at install. The lockfile was regenerated with `npm install --no-audit --no-fund`; the
diff is 4 insertions and 54 deletions, covering the pinned Lovable config version and `dev` flags
on optional platform binaries. No dependency range was upgraded. `npm ci --dry-run` now exits 0.

## Gate defects found and repaired before any product change

1. **Coverage floors were never enforced.** `package.json` ran
   `vitest run --config vitest.config.ts` without `--coverage`, and `vitest.config.ts` does not set
   `coverage.enabled`. Vitest only evaluates `coverage.thresholds` when coverage is collected, so
   the 48/46/39/39 floors in `docs/quality/testing.md` and the "coverage floors" line in `README.md`
   described a gate that could not fail. `npm run test` now collects coverage.
2. **`check:docs` was not in CI.** `.github/workflows/ci.yml` ran typecheck, lint, tests, contrast,
   build and PWA integrity, while `AGENTS.md` and `DEFINITION_OF_DONE.md` make the documentation
   gate part of "done". CI now runs it.
3. **Coverage output was linted.** Once coverage is collected, Istanbul writes
   `coverage/*.js` (`prettify.js`, `sorter.js`, `block-navigation.js`), which `eslint .` then
   scanned; its vendored `eslint-disable` comments produced three warnings and failed
   `--max-warnings 0`. `eslint.config.js` now ignores `coverage`, and `npm run verify` passes with
   the report present.

All three are gate integrity, not product behaviour: no threshold was lowered, no test was
skipped, and no assertion was weakened.
