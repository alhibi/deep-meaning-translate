# Upgrade Audit — 2026-11-17

Status: **Executed**. This records what was diagnosed, changed and measured on 2026-11-17 against the
published tree (`origin/main` `fddded4`). Evidence classifications follow
[testing](../quality/testing.md): VERIFIED / OBSERVED / SUSPECTED / NOT_VERIFIED. No claim below is
made from a README or an older report.

## 0. Scope and method

- The working copy was 13 commits behind the published branch; it was fast-forwarded (no rewrite,
  no force-push) so the audit ran against exactly the published code plus this work.
- Baseline before any change: `npm run verify` green (79 files, 514 tests, 4 skipped), `npm run build`
  green, contrast 51/51, docs 54/54. Production preview and the Android toolchain were exercised.
- Every area was read before it was touched: the translator route, `ComposerField`, the request
  hook/scheduler/stream, providers and prompts, the enrichment queue, the lexicon and the sentence
  shadow, persistence/history/statistics, the native handlers and the Android shell.
- Work was split across disjoint ownership areas (providers, lifecycle/queue, storage, dictionary,
  shadow, docs) with the composer, public page, integration, Android and the release gates owned by
  the lead. Each fix carries a regression test that fails on the previous behaviour; tests were never
  weakened.

## 1. Findings and root causes

The full register with evidence lives in [technical-debt.md](technical-debt.md) (D51–D73, TD38–TD43).
The four findings that matter most:

| # | Finding | Root cause (evidence) | Fix |
| --- | --- | --- | --- |
| F1 | **The installed Android app put the text field (and its caret) off its canvas.** A restored German draft rendered as fragments at the right edge; in RTL the native caret sat hundreds of pixels from the field's start — the reported "caret far from the expected typing start" | A dead `@keyframes bead` animated `inset-inline-start`. The Android build targets a Chrome 80 WebView, so Lightning CSS lowers logical properties; inside a keyframe it hoisted the physical `left/right: calc(100% - 1.125rem)` out and scoped it to the next rule — `.composer-editor`. Measured from the packaged build's DOM: editor `x=362, width=348` inside a 412-wide viewport; the built CSS contained `.composer-editor:not(:lang(...)){left:calc(100% - 1.125rem)}`. Web builds were unaffected (no lowering), which is why every browser test stayed green | Deleted the dead keyframes/utility (the switch bead is transform-only), pinned `text-rendering: auto` so the mirror cannot measure different lines than the field, and added two guards: `scripts/prepare-native-web.mjs` fails the native build if `.composer-editor` ever gets a physical left/right offset, and `src/lib/styles.test.ts` fails if any `@keyframes` animates a logical property. Verified on emulator-5554 / WebView 124: editor `x=32, width=348`; empty RTL caret painted at device x 995–997 against an expected 997.5 (≈1 device px) |
| F2 | **The StrictMode remount slot silently dropped every streamed word in development** (and any double-invoked effect tree) | The new unmount latch (`disposed.current = true`) had no re-arm. Logged order: effect mount → cleanup → effect mount; the first stream callback saw `disposed = true` and was dropped | Re-arm `disposed.current = false` when the effect mounts, keep the latch on cleanup; the browser suite ("deleting words displays a shorter stream") now passes |
| F3 | **One request body for every model task** — thinking disabled, temperature and JSON fixed for live text, settled JSON, repair, review and analysis alike, and analysis ceilings sized from prompt characters | Verified against DeepSeek's docs (2026-11-17): the model thinks by default; thinking is a request field; reasoning is charged against `max_tokens` (live probe: `max_tokens:10` + thinking returned `length` with an empty answer) | `providers/capabilities.ts`: one table of task profiles (live/full/repair/review/analysis → thinking, effort, temperature, JSON, ceiling), `assertContextFits` for impossible input, and non-streaming replies now go through the same completion contract as streams |
| F4 | **Quiet work could accumulate and cost requests nobody needed**; same for canonically equal drafts | The enrichment door was a plain serialized tail with no validity/cancellation/priority; request identity collapsed whitespace without Unicode composition | Bounded priority queue (max 12, review > dictionary > shadow) that skips obsolete queued work before any network call and logically aborts running work; NFC-canonical request identity |

Additional proven defects (details and evidence in the register): shadow anchors on repeated words could
point at the wrong sentence and diacritics/tatweel/decomposed letters were unanchorable; long paragraphs
(>600 chars) were excluded from the shadow; the dictionary refused real idioms and never carried the
sentence/register; the hidden mirror could measure different lines than the field (`text-rendering`);
archive counts drifted past the limit; a stale tab's whole-array save could erase another tab's rows;
native statistics re-transferred up to 2,000 rows after a tag correction; concurrent native saves could
lose a row; `saved.find` normalised the whole phrasebook per render; the stats route ran eight
full-archive passes per render; a stream abort did not unblock a hung reader; the review ran outside the
paced door; lexicon/shadow caches could collide or show a stale entry.

## 2. What changed

### Public page and navigation
- The translator keeps **one** quiet footer entry ("عن today" / "About today" / "Über today") opening
  `/about`: product and philosophy, how a translation is made, on-device data, what is sent and why,
  third parties and limits, then the controls (`DataControls`, Android `ProviderKey`,
  `DiagnosticsPanel`).
- `/privacy` → **301** `/about#privacy`; `/arabic-german-translation` → **301** `/about#translation`.
  The sitemap is `/` + `/about`; canonical is self; metadata is localized per the interface language.
- The privacy copy was re-audited against the code: the active provider, background analysis requests,
  the Android direct-key path and its boundaries, hosting metadata, and the absence of a contact address
  are now stated accurately. Review date: 17 November 2026.
- Files: `src/routes/about.tsx` (new), `src/routes/privacy.tsx`, `src/routes/arabic-german-translation.tsx`,
  `src/routes/index.tsx`, `src/lib/i18n.ts`, `tests/e2e/seo_navigation.py`.

### Composer
- The visible "translates as you type" caption is gone; the meaning stays in the composer's
  screen-reader description, and no translation logic changed.
- The mirror now repeats the field's direction explicitly; `.composer-editor` pins `text-rendering`.
- The dead `bead` keyframes that broke the Android layout are gone, with a build guard and a source
  test (F1).
- Files: `src/components/translator/ComposerField.tsx`, `src/styles.css`, `src/lib/styles.test.ts`,
  `scripts/prepare-native-web.mjs`, `src/routes/index.tsx`, tests.

### Requests, streams, providers
- Per-task capability profiles; explicit thinking; reasoning-aware ceilings (live 8,192 / full 16,384 /
  repair and review 32,768 / analysis 65,536, under the provider's documented 384K); context-fit guard
  (loud `input` error instead of a split or a silent cut); completion contract for streaming **and**
  non-streaming replies; the direct Android reader enforces the same contract; caller abort cancels the
  response reader and is never retried or salvaged.
- Files: `providers/capabilities.ts`, `providers/completion.ts`, `providers/deepseek.server.ts`,
  `providers/opencode.server.ts`, `providers/retry.server.ts`, `direct.ts`, `budget.ts`, `stream.ts`,
  `scheduler.ts`, `useTranslator.ts`, `engine.server.ts`.

### Background work
- One bounded priority door for dictionary, shadow and the quiet review; obsolete queued work is pruned
  before a request, running work is logically aborted, the gap is only spent by work that reached the
  network, and a hung task releases the door.
- Files: `enrichment.ts`, `useLexicon.ts`, `useShadow.ts`, `useTranslator.ts`.

### Storage and statistics
- Whole-array web writes reconcile against the stored document before writing; native statistics keep a
  complete-window cache (no re-transfer on a tag correction); `history.count` is clamped; derivation is
  memoised per archive array with a bounded key map; the stats route builds its on-device-estimate counts
  in one pass.
- Files: `history.ts`, `saved.ts`, `persistence/web.ts`, `stats/engine.ts`, `stats/moments.ts`,
  `stats/useArchive.ts`, `stats/memo.ts` (new), `persistence/storage.bench.test.ts` (new), `routes/stats.tsx`.

### Dictionary (lexicon v2)
- A lexical reference rather than a card of alternatives: term/lemma/part of speech, in-context ranked
  readings, labelled forms (German gender/article/plural/cases, principal parts; Arabic root, pattern,
  masdar, gender, plural, dialect spellings), synonym and near-synonym distinctions, collocations,
  example pairs, pronunciation only when confident, register/variety — and an explicit
  "model reading, not a verified dictionary" label.
- The gate now accepts idioms and short fixed expressions (≤96 code points, ≤10 words, inner
  comma/apostrophe/hyphen; sentences, terminal punctuation and pronoun-built clauses refused) and sends
  the sentence and register for ranking. Prompt and parser live together in `lexicon.ts`; the server
  function only calls `runAnalysis`.
- Files: `lexicon.ts`, `lexicon.functions.ts`, `useLexicon.ts`, `LexiconPanel.tsx`, `LexiconSheet.tsx`,
  `routes/api/native/v1/lexicon.ts`, native handlers, tests.

### Sentence Shadow (v2)
- Anchoring is now occurrence-aware and context-paired (a repeated phrase maps to the occurrence its
  counterpart points at); NFC-aware folding maps back to exact offsets (harakat, tatweel, decomposed
  German letters, punctuation/whitespace adjacency); anything that cannot be anchored in both texts is
  dropped.
- The vocabulary separates genuinely lost meaning (`loss`) from weakened tone (`weakened`); stylistic
  or acceptable cross-language differences are not shown as losses and an honest "nothing essential
  lost" is the normal answer. Thresholds were re-tuned and capped at four findings.
- Long paragraphs are analysed in sentence-aligned overlapping windows with absolute offsets, ordered
  context and at most four deep calls.
- Restores preserve facts, numbers and names, must touch the lost words, and are previewed as a word-level
  diff before applying; the sentence is re-checked after applying, the other findings stay, and undo is
  no longer timer-bound.
- The map shows both texts in full with linked, numbered spans: clicking one highlights its counterpart
  (side-by-side where there is room, stacked on the phone), with strength and confidence as separate
  measures.
- Files: `shadow.ts`, `shadow.functions.ts`, `useShadow.ts`, `ShadowSheet.tsx`, `SentenceShadow.tsx`,
  `routes/api/native/v1/shadow.ts`, `tests/eval/shadow_eval.ts`, `tests/e2e/shadow.py`, tests.

## 4. Risks and external requirements

- **No release APK**: the repository has no upload keystore in this environment and signing fails
  closed (TD18). A publishable artefact needs the owner's four signing variables.
- **No connected instrumentation run** and no API 24–29/OEM/foldable device (TD17/TD42).
- **Provider quality is not certified**: there is still no reviewed corpus (TD1), so dictionary and
  shadow output are labelled as model readings, not verified lexicography.
- **Long-text shadow cost** is bounded (≤4 deep calls × 45 s budget) but not measured live (TD41).
- **Enrichment cancellation is logical, not over the wire** (`rpc.ts`/`nativeJson` accept no signal) —
  TD38; the direct Android path also cannot abort a body after hand-off (TD40).
- **Deployment-wide rate limiting** remains a hosting-edge responsibility (TD5); the app keeps its
  per-purpose process-local buckets.
- Existing accepted behaviour: two up-to-date tabs resolve by last write (TD33); visual regression
  testing is manual (TD4); the E2E suite is not in CI (TD3).
